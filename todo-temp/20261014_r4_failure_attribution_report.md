# R4 新规则为何没有修复目标错误

2026-10-14。对象：`outputs/ncbi_disease/20260802_gpt54-high_moderation`（GPT-5.4 high，dev10）。逐例细节见[规则链报告](r4-rule-chain/20261014_r4_rule_chain_report.md)和[隔离对照报告](r4-isolation/20261014_r4_isolation_report.md)。

## 1. 问题

R4 针对 3 个漏标（gold 为 SpecificDisease，模型未标）生成了一条新规则：

> "缺乏/活性降低"加具体分子，出现在定义或因果语境中，就标为 SpecificDisease。

开发 F1 从 0.8873 升到 0.9091，但逐例看并没有修好什么：

| 目标 | R0 至 R3 | R4 |
| --- | --- | --- |
| FALDH（deficient activity of fatty aldehyde dehydrogenase） | 一直 O | O |
| G6PD（deficiency in G6PD） | 一直 O | O |
| PAH（deficiency of hepatic phenylalanine hydroxylase） | R0 至 R2 正确，R3 丢失 | 恢复 |

长期漏标的修复数是 0/2。唯一的"修复"只是撤销了 R3 造成的回归。

同时，R4 指南里有三处写着"FALDH 不标注"，与 gold 相反。

## 2. 原因假设

| 假设 | 若成立，应看到 |
| --- | --- |
| A　FALDH 是规则冲突：新规则放行，指南里的点名排除仍禁止 | 只给规则时能标出；用完整指南时标不出；删去点名排除后恢复 |
| B　FALDH 与排除无关：模型本身就不把它读作疾病 | 只给规则时也标不出 |
| C　规则的例外从句（exception rule）拦住了目标 | 删去例外从句后能标出 |
| D　G6PD 是规则本身不够 | 只给规则时也标不出 |
| E　R3 的例外条款造成了 PAH 回归 | R3 指南下错，R4 指南下对 |

A 和 B 对 FALDH 的预测相反，实验可以在两者之间作出区分。

## 3. 实验与设计思路

**1. 规则链追踪（离线，不调用模型）**

- 做法：逐个案例检查四个步骤的输入和输出，即错误解释、写规则、改写指南、重新标注。
- 目的：找出案例在哪一步丢失，以及冲突文字从哪里来。
- 对照：另取 top-4 和 dev30 两个 run 做同样的追踪。这两个 run 展示的示例文档不同，构成天然对照。

**2. 隔离对照（36 次调用）**

- 固定项：模型和设置与原 run 相同，标注时不给 gold。
- 变量：只换指南文本。
- 规模：3 篇目标文档 × 4 种条件 × 3 次重复。重复是因为同一指南的标注结果本身会波动。

| 条件 | 指南文本 | 检验什么 |
| --- | --- | --- |
| ① | R3 指南 | 基线 |
| ② | 类别定义 + 新规则 | 规则本身是否有效（A、B、D） |
| ②b | 同 ②，删去例外从句 | 例外从句是否拦截（C） |
| ③ | R4 指南 | 整合进完整指南后是否有效 |

**3. 追加对照 ③−（3 次调用）**

- 做法：R4 指南只删去点名 FALDH 的三处文字，其余不变。
- 目的：③ 与 ② 相差近 2 万字符，嫌疑不止点名排除。③− 只改这一个变量。

## 4. 结果

### 4.1 规则链：FALDH 在哪一步丢失，冲突文字从哪里来

FALDH 在 R4 四个步骤中的经过：

| 步骤 | 这一步看到了什么 | 这一步做了什么 | 对 FALDH 的影响 |
| --- | --- | --- | --- |
| 错误解释 | FALDH 作为错误例出现，带有 gold 标签 SpecificDisease | 指出这类短语容易被误读成"生化异常"，建议在定义句里标为 SpecificDisease | 方向正确 |
| 写规则 | 上一步的解释和错误例 | 写出新规则，正好覆盖 FALDH；同时附了一个例外从句："仅指孤立生化发现时不适用" | 方向正确 |
| 改写指南 | 当前指南（R3 已写有两处"FALDH 不标注"）、新规则、"不许破坏的示例"（其中有 FALDH 所在文档的全文，FALDH 未被标注）；**看不到任何 gold** | 把新规则写进指南，但两处旧排除原样保留，又**新增一处**"FALDH 不标注" | **在这一步失败** |
| 重新标注 | 新指南 | FALDH 仍然不标 | 结果仍错 |

**"不许破坏的示例"是怎么来的**：

- 系统按顺序取前 5 篇至少有一个正确标注的开发文档，展示全文，每篇最多列出 5 条已标对的实体。
- 没标出来的 gold 实体不做任何标记。
- 改写指南的模型因此看到 FALDH 这句话"未被标注"，却不知道它在 gold 里其实是实体。

**三个 run 的对照**：

- **主 run**：FALDH 和 norrin 的文档每轮都在示例里，两者都被写成了"不标注"。G6PD 和 PAH 的文档从未进入示例，指南里也从来没有提到它们。
- **dev30**：FALDH 的文档在开发集中，但不在示例里，指南就从来没有提到 FALDH。norrin 的文档在示例里，又被写成了"不标注"。
- **top-4**：G6PD 的文档被展示了，但没有被写进指南。

所以"被展示"是被写成"不标注"的前提，但被展示的不一定都会被写。

### 4.2 隔离对照与 ③−：同一篇文档换用不同指南重标

**怎么读下面的表**：每种条件对每篇文档重标 3 次，表中列出这 3 次分别标成了什么。为了判断"模型的判断变了没有"，区分两种对：

- **完全正确**：跨度和类型都与 gold 一致。
- **类型正确**：类型对，但跨度多了一点。例如把 "( FALDH )" 也算进去了。

② 和 ②b 只有类别定义和一条规则，没有完整指南里"括号中的缩写单独标注"等跨度规则，所以常出现第二种情况。按严格评分它算错，但模型的判断其实已经转向了正确的方向。

**FALDH**（gold：SpecificDisease "deficient activity of fatty aldehyde dehydrogenase"）

| 条件 | 3 次分别标成了什么 | 说明 |
| --- | --- | --- |
| ① R3 指南 | 不标、不标、不标 | 复现了原来的错误 |
| ② 类别定义 + 新规则 | SpecificDisease（含 "( FALDH )"）×2；1 次把它和前面的 ichthyosis 等症状合成一个 CompositeMention | 3 次都把它当作疾病，其中 2 次类型正确 |
| ②b 同 ②，删去例外从句 | 与 ② 相同 | 例外从句有没有，结果一样 |
| ③ R4 指南 | 不标、不标、不标 | 规则一放进完整指南就失效 |
| ③− R4 指南删去三处"FALDH 不标注" | 3 次都完全正确 | 只删这三处就修好了；整篇 14 个实体 3 次全对，也没有误标 |

**读法**：② 能标、③ 不能标，说明是完整指南里的某些内容拦住了它。③− 进一步表明，拦住它的正是那三处"不标注"。

**G6PD**（原句 "...is responsible for enzyme deficiency in G6PD A-..."，gold 只标 "deficiency in G6PD"，类型 SpecificDisease）

| 条件 | 3 次分别标成了什么 |
| --- | --- |
| ① R3 指南 | 不标；"enzyme deficiency in G6PD A-" 标为 DiseaseClass；不标 |
| ② 类别定义 + 新规则 | 不标；"enzyme deficiency" 标为 DiseaseClass；不标 |
| ②b 同 ②，删去例外从句 | "enzyme deficiency" 标为 DiseaseClass，3 次相同 |
| ③ R4 指南 | 不标、不标、不标 |

**读法**：没有任何一种条件把 "deficiency in G6PD" 标成 SpecificDisease。删去例外从句后，模型标注这句话的次数从 1 次增加到 3 次，但标的是 "enzyme deficiency"，类型是泛指的 DiseaseClass，仍然不是 gold 的读法。所以问题不在冲突，而在于规则描述的"缺乏 + 具体分子"结构，和模型对这句话的理解对不上。

**PAH**（gold：SpecificDisease "deficiency of hepatic phenylalanine hydroxylase"）

| 条件 | 3 次分别标成了什么 |
| --- | --- |
| ① R3 指南 | DiseaseClass ×3，类型错 |
| ② 类别定义 + 新规则 | SpecificDisease（含 "( PAH )"）×2，完全正确 ×1 |
| ②b 同 ②，删去例外从句 | 与 ② 相同 |
| ③ R4 指南 | 3 次都完全正确 |

**读法**：R3 指南下 3 次都错；保存的 R3 结果是"不标"，这次是"标成 DiseaseClass"，但都是错。R4 指南下 3 次都对。所以 R4 对 PAH 的修复是稳定的，修复的是 R3 弄坏的东西。

### 4.3 两点补充

- **③ 组的 3 次结果与保存的 R4 结果完全一致**：FALDH 不标、G6PD 不标、PAH 正确。R4 的失败不是偶然。
- **② 和 ②b 只能当作探针**：这两组在 FALDH 那篇文档中丢掉了 2 至 3 个原本标对的 DiseaseClass（如 mental retardation），因为极简指南缺少相关细则。它们只能用来回答"这条规则能否改变目标案例的判断"，不能当作可用的指南。

## 5. 结论

- **FALDH：A 成立，B 不成立。** 新规则是有效的，被三处与 gold 相反的"不标注"抵消了；删去这三处，就能修好。
- **例外从句不是 FALDH 的障碍。** ② 与 ②b 结果相同。
- **G6PD：D 成立。** 规则描述的结构和这句话对不上。去掉例外从句，也只得到错误的标注。
- **PAH：E 成立。**
- **修正 10/07 的说法。** 原说法是"排除示例是症状而非成因"。更准确地说：FALDH 的原始漏标早于任何排除文字，那是模型自身的判断；但 R4 修不好它，原因就是排除文字。
- **对方法的含义。** 改写指南这一步缺少 gold，会写出有害的冲突文字。这支持两个方向：方案 A，给这一步提供错误案例的 gold；方案 B，写完后用开发 gold 检查冲突。现有的 P4 扫描器漏掉了这些冲突，检查器本身需要先验证。
- **局限。**
  - 每格 3 次、3 篇开发文档、单一模型。
  - ③− 只验证了 FALDH 一个案例。
  - "方向正确"这一口径是看过第 1 轮结果后才确定的。
