# 研究计划修订版：抽象反馈如何支持可靠的指南改进

2026-10-19。供 2026-10-20 会谈使用，实验窗口拟为 10/21 至 12/1。本稿保留长期逼近强基线、降低专家标注负担的目标。新增实验全部未执行，调用数量为规划值，不构成付费授权。

## 1. 目标、现状和主问题

目标是在少量人工监督下改善新文档的标注质量，并明确哪些收益可以重复、哪些仍需专家复核。当前 NCBI Disease 的历史 valid100 strict F1 为原指南 .7792、Top-1 .7878、Top-4 单条已评分轨迹 .8023；Top-4 的稳定优势尚未确立。四子类型评分与历史 BioBERT 单 Disease 成绩不同，暂不宣称达到或距当前 SOTA 还有某个可比的精确差值。

**主要问题：当改写器不接收实体级答案时，抽象的防回归条件能否保留原方法保护正确行为的功能，并改善最终指南质量？**

动机有两端：保留原实体示例时存在文本吸收和错误排除规则；移除示例的历史实验又没有取得稳定更好的效果。它们说明问题值得检验，没有证明抽象保护一定有效。

## 2. 已确认的监督边界

用户确认：开发集 gold 可以用于上游错误分析和评价，但改写指南的模型只接收抽象原则，不接收实体级答案。

| 环节 | 可以看到 | 不可以看到 |
| --- | --- | --- |
| 上游分析/教师 | 原十篇开发文本、预测及 gold、当前指南 | valid/test gold |
| 改写器 writer | 相同起始指南、抽象新原则；B 臂另有抽象防回归条件 | 原开发文档、MATCHED TP 答案列表、目标实体 gold、字符偏移、案例编号、逐项答案或上游完整对话 |
| 标注器 | 冻结后的指南、待标文本、标签定义 | 待评文档 gold 和教师分析 |
| 外部评分 | 已保存预测及对应 gold | 不把评分反馈送回最终 test 的开发过程 |

抽象信息可以描述类型定义、语言条件、应保留的行为和例外。不能把单个案例换个说法、隐去名字后仍传递答案。使用禁止字段检查、原文字符串检查和人工语义抽查，记录是否通过；字符串检查本身不能证明没有答案信息。

两臂新循环从同一份获准的原始指南开始。原指南自带的规范示例需登记，与后续吸收的开发答案区分。不能直接拿已包含开发实例的 R3/R4 指南来证明新 writer 满足边界。旧完整方法的保存指南仅作冻结性能参照，不再通过其实体级示例通道生成新的改写。

## 3. 唯一主要方法比较

| 条件 | 共同输入 | Writer 的唯一区别 |
| --- | --- | --- |
| A：抽象新原则基线 | 当前指南＋抽象新原则 | 没有额外保护区块 |
| B：抽象防回归条件 | 与 A 相同 | 另收到抽象的防回归条件 |

两臂使用相同教师提示和输出结构。教师均生成“新原则”和“防回归条件”，A 的 writer 隐藏后一部分，B 显示。固定快照试验共享同一教师产物；完整循环中，各臂按自身误差继续，结论针对整个流程。

保护条件须回答：什么一般条件下应保留什么行为；其作用域到哪里；如何避免把未列出的文本当负例。它不能仅要求“不许回归”，也不能不断追加互相冲突的例外。教师产生的条件与新原则相冲突时，记录为失败或待审查，不默认保护条件正确。

同一主对照中不同时加入动态示例选择、额外冲突修复、Top-K 变化、模型更换、指南压缩或 reviewer。B 增加的输入 tokens 是实际方法成本，应记录，不能声称计算完全相同。

这组比较回答“抽象保护有没有作用”。旧完整方法、新 A/B 的历史或同期分数可以并列展示，但不同输入和批次的差异不得全归因于抽象保护。

## 4. 分阶段执行与停止条件

### 阶段 0：零模型调用的协议冻结

审计已有指南、哈希、重复轨迹、预测完整率、数据 ID 和 scorer。核对本地实现与基础论文的 discrepancy context、verified examples 含义。保留所有失败或未改善轨迹。

核对原始 test 是否从未被用于看错例、选方向、改提示或选指南。valid100 已参与这些活动，后续明确作为开发评价。若没有真正独立集合，停止使用“未触碰测试集”表述，另定确认来源。

先冻结主要指标、A/B 输入、教师输出格式、轮数上限、重复数、成功标准、预算和时间上限。当前没有授权运行任何付费批量。

### 阶段 1：补齐现存轨迹的评价

先列清原指南、Top-1 和 Top-4 全部现存终版。按哈希识别相同文本，但保留每条轨迹的出现次数。相同文本可减少固定指南评分工作，复用的预测不能当独立重复。

经预算同意后，在同一当前模型和配置下分批评价。原指南＋一个 Top-1＋一个 Top-4 的 300 次标注只是桥接试验，不能证明整个方法稳定。完整补评可包括同期三条 Top-1、三条 Top-4 和原指南，共 700 次；加最初成功两条最多 900 次。是否执行全量，由信息价值和实际预算决定，不默认自动展开。

需要回答：.8023 所代表的成功轨迹是否有代表性；其他终版是否接近原指南；差异来自类型、边界、漏标还是过度标注。历史模型不可恢复时，明确这是旧指南在当前模型上的表现，不能称完全重现历史生成过程。

### 阶段 2：抽象保护的机制试验

先准备双方都合规的起始指南及抽象教师输出。R3/R4 快照可以用于分析来源，但未经审查的实例内容不能进入新 writer。

固定三类开发案例：已有原则可能修复但被指南阻挡的案例；原则本身不足的案例；原本正确且需保护的案例。不要只选 FALDH 成功故事。先记录预期作用和边界，尤其 G6PD 不要求被同一改动必然修复。

小试可用 A/B 各三次改写，每份候选先标三篇预定文档一次。若共享的一次教师生成计入，共约 `1＋2×3×(1＋3)＝25` 次调用，不含失败重试。它只检查可行性和局部机制，不证明全 dev 或泛化收益。

只有保护条件确实抽象、能被 writer 保留、目标修复与正确案例保护存在支持信号，才扩展至 dev10 全量重复。两臂各三次改写，每份候选 dev10 标三次为 `2×3×(1＋10×3)＝186` 次，再加教师和审核费用。若没有目标作用、反复出现冲突或回归增加，停止该候选，不启动完整循环。

### 阶段 3：完整 A/B 轨迹

通过机制门且有预算后，两臂各三条独立轨迹，建议上限三轮。共同设置固定：同十篇、同原指南、同模型、同 Top-K、同接受和停止策略、同生成上限。新的重复接受策略不同时作为方法改动。

开发循环评分继续采用项目既有口径，并与外部 strict PubAnnotation 指标分开记录。若改变接受策略，必须双方一致、事前冻结，且不把其收益归因于 B。

完整记录轮数、每次候选、拒绝与接受、解析失败、重试、实际 token、耗时和终版。达到轮数或预算上限停止，不能为追求 .9 无限追加。

### 阶段 4：冻结后的最终检验

在原 test 的独立性确认、提示和指南选择规则冻结后，运行一次事先规定的最终检验。所有预定终版或事先确定的选择规则均要报告，不能看 test 后挑最好指南。检验后不把其个例送回改写。

## 5. 质量指标与三层不确定性

主指标为新文档 strict micro-F1，即汇总 TP、FP、FN 后计算的精确边界和子类型 F1。辅助报告 precision、recall、忽略类型的跨度 F1、各类别计数、目标修复、新破坏及成本。

错误诊断拆为纯类型、纯边界、类型＋边界联合错误，以及漏标、误报、未配对重叠。当前 Top-4 的 57 条 label_mismatch 中只有 41 条纯类型，16 条联合错误；.8750 的模拟不是纯类型修复结果。

分别报告：

1. 固定指南重复标注的波动。
2. 从头生成指南的轨迹差异，每条终版都展示。
3. 有限文档抽样的不确定性，按文档同步重采样两条件，重新计算 micro-F1。

文档 bootstrap 是给定指南和预测的条件性区间，不能代替轨迹重复。三个轨迹也不天然足以证明稳定性，报告均值、范围、每条结果和条件性区间，不夸大统计把握。

原计划 .012 约为两组三次均值差的一个标准误，不是显著性阈值。建议会议选择实际有意义的晋级标准，例如均值提升至少 .01、至少 2/3 轨迹同向且无预先定义的严重回归。这些是**拟议实用门槛**，不是功效计算或显著性证明。阈值在结果出来后不得改变。

文本吸收率、Copied Share、扫描器发现冲突数为辅助指标，先统一实现定义。零报警不等于零冲突，文本重复也不直接等于有害记忆。

## 6. 性能备选和可选 reviewer

若抽象保护小试没有支持信号，优先讨论针对类型或边界的复核，不同时重开全部方向。纯类型复核固定跨度，边界复核单独记录是否允许分拆、合并和新增。

Reviewer 开发试验至少比较：原预测；同一 reviewer 模型独立重新标注；该模型读取旧预测后复核。后两者固定相近额外预算。否则更强基础模型和额外计算都可能解释提升。

dev10 两条件各三次约 60 次新调用。无净改善、明显破坏正确实体或无法遵守权限，就停止，不在 valid 看结果后改提示再宣称一次验证。

报告 fixes/breaks、残留漏标、各类变化及成本。0.9606 只称规定 gold 编辑操作下的模拟分数，不能作为通用专家上界，也不能由 reviewer 与它的差推算人工量。若研究转人工比例，采用不见 gold 的文档选择信号，并同时报告复核覆盖率与未复核错误；真实省时需要真人测量。

## 7. 调用预算与模型选择

以下是计数公式，不是报价，也不是要求全部执行。每阶段独立审查，前阶段不支持就停止。

| 项目 | 规划调用量 |
| --- | ---: |
| 文件、哈希、协议审计 | 0 |
| 最小机制试验 | 约 25，另计审核和重试 |
| 扩展机制试验 | 186＋教师/审核/重试 |
| 三指南当前模型桥接 | 300 |
| 现存重复轨迹完整补评 | 700，另加最初两条时最多900 |
| 可选 reviewer 开发试验 | 60 |

完整 A/B 的通用估算为：

`调用数 = 2L × [(M＋1)DR ＋ MS ＋ VRv]`

L 是每臂轨迹数，M 是最大修改轮数，D 是开发文档数，R 是每版开发标注次数，S 是每轮分析与生成调用数，V 是评价文档数，Rv 是终版评价重复次数。若 `L=3,M=3,D=10,R=1,S=3,V=100,Rv=1`，为 894 次；若 R=2，为1134次。不含失败、repair、供应商轮询收费和额外审核。两臂六份终版再测独立 test100，另需600次。

这说明即使只有一项方法，正式重复评价仍有实际成本。资金不足时先减少候选方向和非必要阶段，不把几十次局部小试包装成完整验证。

原计划日元估计依赖旧单价、输出长度和模型假设，本轮未逐项复核，不沿用为当前报价。先记录实测输入/输出 token 分布、总预算、最大重试、超时和停止上限，再申请执行。64,000 输出上限不是费用上限。

不把廉价模型迁移设成必须先完成的研究主线。若预算迫使更换，在新模型内做完整 matched baseline，桥接至少包含不同长度指南及错误结构；原指南 F1 接近不足以证明研究结论可迁移。

Claude Pro 可先用于受支持界面的少量可行性试验；不含 Console API 额度。正式执行环境必须保存固定输入、原始输出、模型/时间和会话状态，不能假设订阅鉴权能转接通用 Python API。[官方说明](https://support.claude.com/en/articles/8325606-what-is-the-pro-plan)

## 8. 六周安排

| 日期 | 主要工作 | 阶段决定 |
| --- | --- | --- |
| 10/21 至 10/27 | 冻结监督边界、审计论文/实现和数据，整理已有轨迹，核预算后分批补评 | 是否存在稳定性能信号；最终 test 能否保留 |
| 10/28 至 11/3 | 抽象教师格式与约25次机制小试，检查保护条件是否夹带答案 | 通过、停止或改选性能备选 |
| 11/4 至 11/10 | 必要时扩 dev10 机制验证，冻结唯一主比较及预算 | 是否值得启动完整轨迹 |
| 11/11 至 11/17 | 仅运行获准的 A/B，达到预算或轮数上限停止 | 结果与失败全保留 |
| 11/18 至 11/24 | 终版同期评价、冻结分析；可选 reviewer 只有通过开发门才扩展 | 不凭 valid 再优化主方法 |
| 11/25 至 12/1 | 条件满足时独立最终检验，完成质量、成本、负结果与局限 | 图表和论文章节进入写作 |

时间安排不保证试验均有正结果。主方法失败时保留负结果，转向备选须在最终 test 之前重新冻结，不增加无预算的探索轮数。

## 9. 10/20 会谈要决定的六件事

1. 作者原方法的 verified examples 到底保证整篇正确，还是只保证列出的 TP？discrepancy context 在公开实现里如何传递？
2. 是否认可“抽象保护替代实体级示例”作为本期主问题，与作者团队新工作是否重叠？
3. 是否先补评现存 Top-1/Top-4，而非继续生成更多轨迹？可承担多少调用和时间？
4. 原始 test 是否仍未参与任何开发，最终采用哪一套标签、split 和 scorer？能否同条件复评强监督基线？
5. 如果主要方法不能改善全局 F1，是否优先类型/边界复核，而非继续深挖一个罕见案例？
6. 没有真实专家研究时，是否把长期减负目标对应的本期结果限定为流程质量和模拟复核覆盖率？
